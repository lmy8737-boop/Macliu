# 结构化数据字段规范

投研笔记正文负责"解释"，可复用的数字应该单独沉淀到结构化数据表（CSV 或类似格式），方便下次直接查表而不用重新翻文章。本文件给出最小字段集，供你新建数据表时参考。

## 最小字段集

任何一张结构化数据表，每一行至少应该包含：

| 字段 | 说明 | 示例 |
|---|---|---|
| `entity` | 这行数据描述的对象（公司/行业/指标名） | 某公司代码、某行业名称 |
| `metric` | 具体指标名称 | 营收、毛利率、市场份额、打分值 |
| `value` | 数值 | |
| `unit` | 单位 | 亿元、%、倍 |
| `period` / `as_of` | 数据对应的期间或时点 | 2026Q2、2026-09-07 |
| `source` | 数据来源 | 公司财报、某数据库、某研报 |
| `source_level` | 来源等级 | P0 / P1 / P2 / P3 |
| `claim_type` | 主张类型 | fact / third_party_view / guidance / model / scenario |
| `verification_status` | 验证状态 | original_checked / independent_cross_checked / single_source_unverified / conflicted / unverified |
| `note` | 备注（口径说明、异常值解释等） | |

## 使用原则

1. **优先向已有主表追加新一行**，不要每次新建一个内容重复的滚动副本——同一个指标、同一个实体的历史序列应该沉淀在同一张表里，方便画趋势图或做回测。
2. **不同职责的数据可以分表**，但要有一个索引/README 说明每张表是干什么用的、字段口径是什么，避免时间长了自己都忘记某张表的含义。
3. **历史快照不要覆盖**——需要修正数据时，保留旧版本行并在 `note` 里写清楚订正原因和日期，而不是直接改掉旧数字。这样出错时能追溯"当时为什么会算错"。
4. **不要因为抓取时间变了就新建副本**——同一份数据只是重新拉取了一遍，应该更新/追加对应 `as_of` 的那一行，不需要新建一张新表。
5. 需要做《打分体系回测方法》里的 IC 检验时，打分历史记录（日期+分值）就是这类结构化数据表最常见的用途之一。

## 示例：一张行业景气度打分追踪表

```csv
entity,metric,value,unit,period,source,source_level,claim_type,verification_status,note
某产业链,景气度打分,0.24,score,2026Q1,内部评估,P1,model,unverified,首次打分
某产业链,景气度打分,0.30,score,2026Q2,内部评估+新增公告交叉验证,P1,model,independent_cross_checked,Q2上调原因见对应笔记
```
