# 证据分级与时效

本文件定义投研过程中每一条数据/主张的分级标准。目的：把"我觉得""大家都说""公告写的"这三种完全不同可信度的信息，用统一的标签区分开，不让预测、第三方观点冒充已发生的事实。

## 一、来源权威性分级 P0-P3

| 等级 | 来源 | 用法 |
|---|---|---|
| **P0** | 财报/公告/监管文件、官网和官方技术资料、客户/供应商官方稿、结构化行情财务数据（交易所/官方数据商） | 事实底座，可直接引用 |
| **P1** | 可信事实类新闻、行业协会、政策原文、学术论文、可验证的产业调研、买方或买方风格独立研究 | 补足 P0，仍是事实类信息 |
| **P2** | 卖方研报/纪要/专家会、目标价、盈利预测和产业图谱 | 属于他人观点、线索和假设，不是事实 |
| **P3** | KOL、自媒体、社群转述、匿名截图、小作文 | 仅作待验证线索，不得作为结论依据 |

**卖方材料不是禁用，但必须标注机构名、标题/主题、日期，并说明借用了哪部分内容**；目标价、盈利预测、市场份额、空间测算、订单推断这类内容，永远是 P2 观点，不能写成事实。涉及全球供应链格局、市场份额、BOM 拆解时，海外大投行的覆盖通常比本地券商更少受"本地映射偏见"影响（本地覆盖容易把边缘参与者误判成龙头、遗漏非本地上市的真正龙头）——同一问题上，优先看跨国投行观点，再用本地券商补充。

## 二、主张类型 `claim_type`

一条信息必须先分类，再决定怎么用：

| 值 | 含义 |
|---|---|
| `fact` | 已发生、可核实的事实（营收数字、公告内容、已完成的交易） |
| `third_party_view` | 别人的判断（分析师观点、管理层措辞、媒体评论） |
| `guidance` | 公司自己给的前瞻指引（不是已实现的结果） |
| `model` | 你/AI 自己算出来的估算、模型输出 |
| `scenario` | 假设性的未来情景，不是预测 |

**红线**：管理层指引、第三方观点、模型结果和未来场景，任何时候都不得写成"已经发生的事实"。

## 三、验证状态 `verification_status`

| 值 | 含义 |
|---|---|
| `original_checked` | 已核对到单份一手原文（如公告原文、财报原表），但只是单一来源 |
| `independent_cross_checked` | 至少两个**信息链真正独立**的来源，对同一口径数字交叉验证，偏差 ≤2% |
| `single_source_unverified` | 只有单一来源，尚未核对到一手原文 |
| `conflicted` | 两个及以上来源数字不一致，偏差 >2% |
| `unverified` | 尚未核实 |

**两条关键规则**：

1. **交叉验证容差**：两个独立来源对同一口径数字交叉验证，偏差在 **1-2% 以内**才算"证实"（`independent_cross_checked`）；超过 2% 记为 `conflicted`，必须并列写出两个数值、各自标来源，不能取平均值或随便选一个。
2. **区分"独立"和"同源转述"**：如果两份材料其实来自同一份底层材料（比如同一份合同、同一场投资者交流会的两次转述），即使数字精确重合，也不能标"独立双源证实"——先判断信息链是不是真的独立，再决定验证等级。单份 P0 原文核对到的状态是 `original_checked`，不会因为"看起来很权威"就自动升级成独立双源。

## 四、获取状态 `retrieval_status`

`ok` / `partial`（部分获取）/ `empty`（无结果）/ `stale`（数据过期）/ `error`（获取失败）。

`retrieval_status` 和证据等级、主张类型、验证状态是四个互相独立的维度——获取成功（`ok`）不代表数据新鲜，也不代表主张已经过验证。**工具（搜索引擎、数据库API、研报库）只表示"我是怎么拿到这条信息的"，不能自动决定这条信息的可信度**：同一个数据库既可能吐出一手财报数字，也可能吐出别人转述的传闻，必须按内容本身重新分级，不能因为"是从某个权威数据源拿到的"就默认高等级。

## 五、时效性分级 T0-T2

| 时效 | 数据类型 | 规则 |
|---|---|---|
| **T0 日频** | 股价、市值、PE/PB/PS/EV、汇率、商品价格、利率、指数点位、现价对目标价的空间 | 只用当日实时行情源；**任何离线快照/缓存数据库都不能用于 T0**；市盈率、估值空间、市值这类衍生指标必须用当前实价自己算，不能引用别人算好的旧数字 |
| **T1 季频** | 最新一期财务数据、公司指引、产能、出货量、机构持仓 | 可以用财务/研报数据库辅助，但必须核对是不是最新一期、时间戳是否清楚标注 |
| **T2 慢变量** | 商业模式、技术路线、竞争格局、长期市场份额结构 | 按数据来源自身的权威性取数，仍然要标日期——"慢变量"不代表永远不变 |
| | | 引用自己旧笔记里的 T0/T1 数字之前，必须先刷新，不能拿几周前的价格/估值当现在的结论用。 |

## 六、旧标签兼容映射（可选）

如果你之前用过 `[V]`/`[A]`/`[S]`/`[E]`/`[X]`/`[?]` 这类简写标注证据状态，可以按下表映射到本规范，逐步替换：

| 旧标签 | 含义 | 对应新标签 |
|---|---|---|
| `[V]` | 已验证 | `independent_cross_checked` |
| `[A]` | 已核对官方单一来源 | `original_checked`（若确认是官方单源）；否则 `single_source_unverified` |
| `[S]` | 单一来源 | `single_source_unverified` |
| `[E]` | 估算/情景 | 不是验证状态，是 `claim_type=model` 或 `claim_type=scenario` |
| `[X]` | 冲突或已否认 | 来源冲突记 `conflicted`；已被公司/权威方否认记 `fact + original_checked`（否认本身是一条事实） |
| `[?]` / `[ ]` | 不确定 | 按上下文映射为 `unverified`、`single_source_unverified` 或 `retrieval_status=empty` |
| `[N/A]` | 无数据 | 只描述获取状态 `empty`/`error`，不能当验证状态用 |

## 七、能从一手源拿到的数据，不允许只抄卖方研报

营收、利润、EPS、毛利率、业务结构、股东信息——这类数据永远能在财报/公告里找到原文，**不允许**只从卖方研报里转引一个数字就标记为"已核验"。卖方研报里出现的这类"事实"，本质仍然只是"卖方帮你定位了一手来源在哪"，不能替代你自己回到公告原文核对。
