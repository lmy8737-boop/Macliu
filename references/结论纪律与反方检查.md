# 结论纪律与反方检查

投研工作里最容易出问题的不是"数据不够"，而是**结论写得比证据支撑的更确定**。本文件定义几个强制性的自检环节，专门用来防止这件事发生。

## 一、关键变量清单方法论

`Y`/`R` 级任务（涉及分析、预测、估值、交易的任务）开始时，先写一句话论点，再列出关键变量：

- 常规研究：**5-12 个**关键变量
- 正式深度报告：**10-20 个**关键变量

**不为了凑数量硬拉长表格**——只保留真正会改变收入、利润、估值、订单真实性、竞争地位或结论方向的变量。

每个变量至少要记录：

| 字段 | 说明 |
|---|---|
| 当前值/主张 | 这个变量现在的数值或状态是什么 |
| 为什么重要 | 它如何影响最终结论 |
| 来源 | 数据/信息从哪来 |
| 来源等级 | P0-P3（见《证据分级与时效》） |
| 主张类型 | fact / third_party_view / guidance / model / scenario |
| 验证状态 | original_checked / independent_cross_checked / single_source_unverified / conflicted / unverified |
| 获取状态 | ok / partial / empty / stale / error |
| 数据时点 | as_of，这个数据是哪一天/哪一期的 |
| 结论敏感度 | A / B / C |
| 证伪条件 | 什么情况出现说明这个变量的判断错了 |

按对结论的影响分级：

- **A 级**：单项错误就足以推翻核心论点，或显著改变估值/交易动作。**A 级变量必须回到一手来源核验**——不能因为"好几个信息源都这么说"就跳过这一步。
- **B 级**：会改变情景发生的概率，但不会单独推翻主线判断。
- **C 级**：背景信息或解释性变量，重要性较低。

## 二、共识差异四问

公司研究、主题筛选和任何"可投资"的结论，必须固定回答这四件事：

1. **市场共识**：当前价格和主流观点相信的是什么？
2. **本库差异化判断**：你和市场共识具体差在哪一个关键变量上？——不能写"空间更大"这种笼统的话，要精确到具体变量。
3. **催化剂**：什么可观察的事件，会让这个差异逐渐收敛（被市场重新定价）？
4. **证伪条件**：出现什么数据后，应该主动降级或推翻这个结论？

如果说不清楚"具体差在哪个变量"，往往说明这个结论其实并没有真正的差异化判断，只是换了个说法重复市场共识。

## 三、结论强制收口（"镜子测试"）

涉及分析/预测/估值/交易判断的公司研究、主题筛选和可投资结论，正文结尾必须给出一段**强制收口**，五个要素缺一不可，否则不能标记为"结论"：

1. 买/不买（或维持/上调/下调）的理由；
2. 护城河或核心竞争力判断；
3. 价格相对内在价值/情景估值处在什么位置；
4. 下行风险是什么；
5. 一句话结论。

**这五个要素说不完整，只能标记为"证据梳理"或"待补充"，不能直接结束全文假装已经有了结论**。证据确实不足时，就如实写"证据不足以支撑收口"，不要为了凑格式硬编一个判断出来。这个环节因为要求把所有分析压缩成一段可以"照镜子"检验的话，逼着你诚实面对自己到底想清楚了没有，所以叫"镜子测试"。

普通快速判断（G 级任务）不强制走这个收口流程。

## 四、自由反方检查（六问）

行业主题、传闻验证、外部观点核验、预期差判断、受益股筛选和任何"未来会怎样"的判断，必须过一遍这六个问题：

1. **用户/自己原本的判断最可能错在哪里？**——先假设自己是错的，去找漏洞。
2. **这个环节真的是供给瓶颈，还是需求端/叙事端的瓶颈？**——很多"卡脖子"故事其实是需求不及预期，被包装成了供给稀缺。
3. **公司是否存在收入占比、认证进度、订单确定性、毛利弹性或不可替代性方面的错配？**——逻辑对不代表这家具体公司真能受益。
4. **估值、涨幅、卖方覆盖度、社群传播热度和流动性，是不是已经反映了这个逻辑（拥挤度检查）？**——好故事被讲烂了，也是一种风险。
5. **最终应该保留主线、降级观察、剔除，还是暂缓判断？什么证据会推翻这个结论？**
6. **点名最强反方**：具体是哪家机构、哪位专家、哪类数据在持相反判断？他们的核心论据是什么？——不能写成"部分投资者担心……"这种含糊说法，必须具体到人/机构/数据。

第 6 条是最容易被跳过、但价值最高的一条——大部分"反方检查"写成了自己想象出来的稻草人反方，而不是市场上真实存在的、有实力的反方。

## 五、两条正交维度不能混

风险等级（G/Y/R）和"角色参与了多少人/是否走了完整流程"是两件不同的事：

- 角色参与得再多、讨论得再充分，也**不会**自动把 R 级降级为 Y 级——涉及真实交易动作的判断永远是 R 级，只能给建议。
- 反过来，一个 G 级的简单数据核对任务，也不需要强行拉一堆角色来"讨论"，那样反而是效率浪费。

风险等级决定"AI 能自主走到哪一步"，运行模式（见《团队协作与角色调度》）决定"由谁、以什么方式参与"，两者分开记录，不要混用。
