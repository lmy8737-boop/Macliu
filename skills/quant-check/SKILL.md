# 量化校验（quant-check）

你现有的七张表打分体系是"专家判断 + 证据分级"，本 skill 不替代它，只给关键判断加一层**可回测的统计校验**——把"我觉得表2升是领先信号"变成"历史上 IC=0.15，n=14，方向对但样本偏少"。

**不做**：系统化多因子选股、模型训练、参数寻优、组合优化。要做这些是完全不同量级的工程，参考 `qlib`，本 skill 不覆盖。

## 环境

固定装在独立虚拟环境，不碰系统 Python：

```bash
source ~/.venvs/quant-check/bin/activate
```

已装：`alphalens-reloaded 0.4.6`（截面多资产分层用，本 skill 脚本目前不依赖它）、`vectorbt 1.0.0`（固定 `plotly==5.24.1` 以兼容，勿升级 plotly，会破坏 vectorbt 内部模板注册）。

## 两个工具

### 1. IC 检验：这个打分历史上有没有预测力

```bash
python3 scripts/ic_check.py --factor factor.csv --price price.csv --periods 21 63 126
```

- `factor.csv`：`date,asset,factor` —— 打分变更记录（如表2/表3每次调分的日期和分值）
- `price.csv`：`date,asset,close` —— 对应标的的日频收盘价（用 `stock-data` skill 取数）
- `periods`：向前看多少交易日算收益，默认 21/63/126（约1/3/6个月）
- 输出：Spearman IC（因子值与未来收益的秩相关）、样本量、p值、每条结果配一句话判读

**用 Spearman 秩相关而非 alphalens 引擎**：alphalens 是为"同一天内给一批资产分层排序、比较头尾组收益"设计的截面工具；你的场景通常是单一标的/指数的时间序列打分（表2 risk_score 从 0.24 到 0.30），套 alphalens 分箱机制会在单资产场景下丢光样本。本脚本直接算原始定义的 IC，更贴合实际用例。

**读数原则**：|IC|<0.03 视为无信号，>0.15 视为较强信号——这是经验参考不是学术阈值。样本数 n<12（大多数季度打分历史天然如此）时结论只作方向参考，不构成统计证据，脚本会自动标注 `sample_warning`。

### 2. 规则回测：这条"破阈值就动仓"的规则历史上灵不灵

```bash
python3 scripts/rule_backtest.py --price price.csv --signal signal.csv --asset TEST.SH
```

- 固定规则：分数上穿 `entry_threshold` 买入，下穿 `exit_threshold` 卖出（阈值默认取序列 60/40 分位，可用 `--entry-threshold`/`--exit-threshold` 指定）
- 输出：总收益 vs 买入持有基准、超额收益、最大回撤、胜率、夏普、交易笔数
- 交易笔数 <5 时自动标 `sample_warning`，提示样本不足以下结论

## 何时用

- 总纲第八点五节「打分变更追溯」的 `review_result` 字段要填"这次调分判断对不对"时，先跑一次 IC 检验，把定性回看换成有统计量的依据。
- 第八节「校准回路」例行回看"表X升是否领先XX股见顶"时，同样适用。
- 用户明确问"这条规则历史上灵不灵"、"这个信号有没有预测力"时主动建议使用，不要求用户先懂 alphalens/vectorbt。

## 数据从哪来

价格数据用 `stock-data` skill 取（`kline` 命令导出日频收盘价再转成本 skill 需要的长表格式）；打分数据取自总纲对应 CSV 的历史 `period` 行或调分记录，不重新造数据源。

## 结果如何沉淀

回测结果不建新的正式知识库文件；把关键结论（IC 值、样本量、显著性、一句话判读）写入触发这次回测的 CSV 对应行的 `note` 字段或总纲第八点五节的 `review_result`。原始 JSON 输出可以留在本地 `/tmp` 或 scratchpad，不进 Obsidian 库。

## 已知限制

- 样本量小是这套体系的结构性问题（打分通常季度更新，几年也就十几个观测点），不是脚本 bug——任何结果都要标注置信度，不能包装成"已验证"。
- 单资产 IC 检验对"领先-滞后关系被算反"敏感，反向 IC 不代表打分错了，先看指标本身是不是设计成反向指标（如拥挤度分数），脚本会在 `reading_notes` 里提示。
- vectorbt 的规则回测是"单资产单规则"快速验证，不是组合级风控模拟，交易成本、滑点、流动性冲击都做了简化假设，只用于方向性判断"这条规则历史上大方向对不对"，不能当成实盘可执行的策略验证。
