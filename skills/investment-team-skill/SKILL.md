# Investment Team v6.7.5

面向 Obsidian 行业、公司和科技股研究。本文件是 LIGHT 模式的完整执行协议；历史 patch、Mattermost、旧数据源和机器审计只在 `CHANGELOG.md` 与 `backups/` 中回溯，不得作为现行指令。

触发：投研团队、七人委员会、公司/行业基本面、卡脖子、订单链、持仓/买卖、穿越者、写进知识库前的角色调度。

## 两条正交闸门

| 维度 | 取值 | 含义 |
|---|---|---|
| 自动化风险 | `G` / `Y` / `R` | AI 能走到哪一步 |
| 运行模式 | `FULL_7_AGENT` / `LIGHT_COMMITTEE` / `MANUAL_FALLBACK` | 谁参与、有无独立产物 |

| 风险 | 典型任务 | AI 权限 |
|---|---|---|
| `G` | 采集、刷新、复算、格式/双链 | 可自动完成，保留来源 |
| `Y` | 公司/行业分析、预测、估值、供应链/订单推理 | 暂定结论；先列关键变量，A 级回一手来源 |
| `R` | 买卖/仓位、单一来源重大订单、不可逆动作、即时财报判断 | 只给建议 + 人工必读/裁决清单 |

默认：普通解释 `G`；绝大多数正式投研 `Y`；影响真实交易或缺少纠错时间升 `R`。角色变多不自动降风险。普通投研不调用 Gemini；Gemini 仅工作区总路由用于编程/工程审计，或用户当次点名。

`MANUAL_FALLBACK` 只表示所需工具、网络或独立角色当前不可用：保留 G/Y/R、证据等级、反方和人工裁决边界，明确缺口与替代来源；不得因 fallback 降低 R 级要求，也不得声称已运行独立角色。最小产物是结论、已核证据、未决变量、最强反方和后续补验证清单。

## 论点、证据、反方

Y/R 先写一句话论点，再列关键变量：常规 5–12 个，正式深研 10–20 个。每项记录：当前值/主张、为何重要、source of truth、`source_level`、`claim_type`、`verification_status`、`retrieval_status`、`as_of`、敏感度、证伪条件。字段枚举与旧标签兼容映射统一引用 `research-data-verify/SKILL.md` 的「Canonical Evidence Semantics」；工具名不等于证据等级。

先按变量建立一张共用证据表并指定取证责任；各角色读取与自身职责相关的行，只补充增量判断、假设、反方和证伪条件，不重复搜集同一底层事实，也不复制其他角色全文。这样减少的是重复劳动，不是关键核验：A 级变量的一手来源、时效、口径和复算要求保持不变。若未决 A 级变量、相互冲突的独立信息链或 R 级决策需要独立第二意见，应另设独立取证路径并登记其实际来源；不能只让第二角色复读共用证据表后称“独立验证”。

- **A 级**：单项错误即可推翻论点或显著改估值/动作 → 回公告、财报、监管文件、技术文档、结构化数据或用户原始调研复算。多模型投票不是证据。
- **B 级**：改情景概率，不单独推翻主线。
- **C 级**：背景。
- 用户产业调研、未公开订单保留 `U1_用户一手线索` 来源标签，同时记 `verification_status=single_source_unverified`；可进情景，不升为 P0。

可投资结论固定四格：市场共识 / 本库差异化判断 / 催化剂 / 证伪条件。R 级以及存在未决 A 级变量的 Y 级，追加 3–7 项人工必读/人工裁决。公司深研按需维护管理层兑现总账，不新开常驻角色。

主题、卡脖子、KOL、预期差、受益股必须做自由反方（写入最终稿，不必为轻量任务单独建 `outputs/` 文件）：

- 用户原判断最可能错在哪？先证明是不是瓶颈，再谈谁受益。
- 哪些证据只是 P3 线索？
- 估值、涨幅、卖方覆盖、社群扩散是否已拥挤？
- 哪些公司只是沾边（缺收入占比、认证、订单、毛利弹性或不可替代性）？
- 保留、降级、剔除还是暂缓？什么证据推翻结论？

5 号缺以上任一项 → REJECT 或标高风险未决。

## 分歧处理：两档，别让辩论机制空转

**LIGHT_COMMITTEE 轻量对辩（默认，无需 subagent）** — 这是同一模型基于同一证据表做的多视角压力测试，不是独立审计。出现下列任一情形时，在正文里就地写一个「分歧裁决」小节，三段各 ≤150 字：

- 关键数据存在 ≥2 个互斥口径（如同一 ARR 有官方 run-rate / 另类数据 / 媒体转述三种值）
- A 级变量上，本库判断与市场共识、卖方主流或用户原判断实质相反
- 同一结论的支撑证据里，P0/P1 与 P2/P3 指向相反方向
- 多头逻辑与空头逻辑都能自洽（如"需求真实"与"价格已透支"同时成立）

格式固定：

```markdown
> [!note] 分歧裁决：<一句话说清争的是什么>
> **正方**：<主张 + 最强证据 + 证据级别>
> **反方**：<主张 + 最强证据 + 证据级别>
> **裁决**：<倾向哪边或两造并列 + 理由 + 什么证据出现会翻转>
```

证据不足以裁边时**必须写"两造并列，待 X 证据"**，不许和稀泥取中间值，也不许假装没有分歧。

**FULL_7_AGENT 完整对辩** — 仅当真实启动多角色独立产出、且角色结论冲突时，才走 Phase 5.5（`references/team_debate_protocol.md`，依赖各角色独立 JSON 产出，LIGHT 模式不适用）。

## 数据入口（3 号）

1. `stock-data`：A/H/美股结构化金融数据主入口。权威路径 `../stock-data/SKILL.md`（本包同级目录）。
2. 卖方研报/纪要/产业链/机构观点数据源（本包不含具体实现，示例见 BRM 一类付费研报数据库；没有这类数据源时按《证据分级与时效》把这一层证据标为缺失，不得虚构）。
3. `web-harvest`：官网、公告原文、新闻、政策、补充核验，权威路径 `../web-harvest/SKILL.md`（本包同级目录）。
4. 如果你有自己的行情数据执行层/补充数据源，同样按"谁真正拥有这类数据"接入，不越级当主入口。

失败时只允许写真实错误类型（当前线程未暴露 / 网络失败 / DNS / 认证 / 空结果），禁止把不可见说成“没配置/没脚本”。每个关键数据点尽量 ≥2 独立来源；只有同一口径差异≤2%且信息链独立时才记 `independent_cross_checked`，单份 P0 只记 `original_checked`。

交易任务才启用 czsc / DK，4 号只读算法 JSON，不读图：

```bash
# 缠论；缺失环境时 scripts/setup/auto_setup_czsc.sh 三级 fallback

# DK 民间近似（非东财官方）；以东财客户端为准

```

细节：`references/czsc_auto_setup.md`、`references/dk_band_signal.md`、`references/chanlun_engine.md`。KTV 选美与穿越者法则只在用户要求选股打分、历史类比或叙事阶段判断时加载，普通个股深研不为凑模块强制写入。

## 输出与红线

- 仓位只用百分比，禁止绝对金额，防止反推本金。
- 交易建议若启用风控红线：单票 ≤7%、单行业 ≤25%、总仓 ≤80%、必须止损、单日亏损 ≤3%、月度回撤 ≤8%。
- `FULL_7_AGENT` 中使用独立上下文和产物的 5 号审核以 `STATUS: PASS` 或 `STATUS: REJECT` 结尾；LIGHT 只能称同模型交叉检查，并在最终稿保留反方、未决项和证伪条件。
- HTML 黑金主题仅用户点名可视化报告时使用（`references/report_style_guide.md`）。
