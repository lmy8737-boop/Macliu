# DK 波段信号（民间近似版 v1）

> **v6.4.7 patch（2026-06-02）**：东方财富证券客户端的官方 DK 波段信号是付费增值功能，
> 算法属商业机密未公开，且公开 API（push2 / datacenter / emrnweb 三个域名）均无法
> 直接拉取 DK 字段——已实测三个域名均反爬。
>
> 本模块基于 3 因子合成一个**与官方 DK 设计哲学相近**的近似信号，提供 D（买）/ K（卖）双信号。
> 不保证 100% 还原东财官方算法，仅作为 skill 内置的「波段择时」辅助工具。

---

## 一、与东财官方 DK 的差异声明

| 维度 | 东财官方 DK | 本模块 v1 |
|-----|-----------|----------|
| **数据源** | 私有大数据 + 客户端协议 | 雪球 K 线 + 雪球/东财公开主力资金 |
| **算法** | 未公开（商业机密）| 3 因子投票（开源）|
| **维度** | 板块联动 / 龙虎榜 / 北向 / L2 委托 / ... | 仅 3 个：EMA + 主力资金 + KDJ |
| **延迟** | 客户端实时（Tick 级）| 日级（盘后）|
| **付费** | ✓ 增值会员 | ✗ 纯开源 |
| **可复现** | ✗ 黑盒 | ✓ 100% 可复现 |
| **方向一致性** | — | 大趋势行情通常一致，震荡市可能分歧 |

**警告**：本模块输出**不是**东财客户端里看到的那条 DK 线。两者方向通常吻合（尤其是趋势行情），
但在以下场景可能分歧：
- 横盘震荡（KDJ 频繁穿越 20/80）
- 利好/利空消息驱动的单日急涨急跌（东财含龙虎榜联动判定）
- 北向资金大幅波动（东财含北向因子，本版没有）

## 二、算法（v1）

### 三因子投票

| 因子 | 触发买票（+1）| 触发卖票（-1）| 中立（0）|
|-----|------------|-------------|---------|
| **① 价格趋势** | EMA12 > EMA26 | EMA12 < EMA26 | — |
| **② 主力资金** | 最近 5 日主力净流入累计 > 0 | 累计 < 0 | 资金接口失败时弃权 |
| **③ KDJ-J** | J < 20（超卖）| J > 80（超买）| 20 ≤ J ≤ 80 |

**合成规则**：
- 总票数 ≥ +2 → **D 信号**（买入提示）
- 总票数 ≤ -2 → **K 信号**（卖出提示）
- 否则 `-` 中性

### 趋势天数 / 趋势涨幅

D/K 信号触发后：
- **trend_days** = 当前状态持续的连续交易日数
- **trend_pct** = 当前状态触发日 close → 当前 close 的累计涨跌幅

例如「D 持续 10 天累计 +5%」表示：10 个交易日前触发了 D 信号，期间股价涨了 5%。

## 三、数据源（v6.4.7）

### K 线（价格因子）
- 主源：雪球 v5/stock/chart/kline.json
- 走 `scripts/data/kline_fetcher.py` 已有的 `_xueqiu_session()`

### 主力资金流向（资金因子）
- **主源：雪球 v5/stock/capital/history.json**（沙盒/本地都通，v6.4.7 默认）
  - 字段：items[].amount（主力净流入，单位元）+ items[].timestamp（毫秒）
  - 优点：A 股 + 美股 + 港股全市场覆盖
- **备源：东财 push2 fflow/daykline**（更细致，含小单/中单/大单/超大单分级）
  - 接口：`push2.eastmoney.com/api/qt/stock/fflow/daykline/get`
  - 字段：f51=date / f52=主力净 / f53=小单 / f54=中单 / f55=大单 / f56=超大单
  - 缺点：部分网络环境（如某些 sandbox / 公司防火墙）会被反爬

### 优雅降级
- 资金接口全部失败 → 自动降级为「2 因子模式」（仅 EMA + KDJ 投票，资金票弃权）
- 触发阈值仍为 ≥ 2 票，所以 2 因子模式必须 EMA + KDJ 同向才出信号

## 四、CLI 用法

```bash
# 单标的 DK 信号（含资金流）
.venv-czsc/bin/python scripts/cli/dk_check.py SH601208

# 拉更长历史（默认 120 天 → 改 200 天）
.venv-czsc/bin/python scripts/cli/dk_check.py SH601208 --lookback 200

# 跳过资金流（仅 EMA+KDJ 2 票）
.venv-czsc/bin/python scripts/cli/dk_check.py NVDA --no-fund

# 同时跑 czsc 多周期共振（双引擎对照）
.venv-czsc/bin/python scripts/cli/dk_check.py SH601208 -m
```

════════════════════════════════════════════════════════════════════════

**这个例子的诊断价值**：
- 表面 D 信号（持续 11 天 +7.38%）
- 但**净票数仅 +0**（不是 +2）= D 信号已弱化
- 主力近 5 日净流出 -10.5 亿 + 5/29 高管减持 → **D 信号实际是技术面金叉但资金面已撤退**

→ 与 v6.4.6 报告「东材 KTV C 级 + 4 法则 1.5/4 不进场」结论高度吻合。

## 五、API 用法（嵌入其他报告）

```python
from calc.dk_signal import fetch_fund_flow, compute_dk_signal, summarize

# 1. 拉数据
kline = your_kline_df         # date / open / high / low / close / volume
fund  = fetch_fund_flow("SH601208", lookback_days=120)

# 2. 合成 DK
out = compute_dk_signal(kline, fund)

# 3. 总结
s = summarize(out, last_n=5)
print(s["current"]["state"])       # 'D' / 'K' / '-'
print(s["current"]["trend_days"])  # 11
print(s["current"]["trend_pct"])   # +7.38
print(s["current"]["vote_total"])  # 0（实际很弱）
```

## 六、局限性 & 已知问题

1. **不是东财官方 DK**：方向通常一致，震荡市可能分歧；不能与东财客户端里看到的 D/K 完全互换使用
2. **美股/港股无资金分层**：雪球 capital/history 只给主力净流入合计，不分小单/中单/大单
3. **A 股 14:55 之后才稳定**：东财备源接口在收盘后才更新当日数据，盘中读到的可能是 T-1
4. **新股不准**：上市不足 26 个交易日的新股 EMA26 不收敛，信号不可信
5. **退市/停牌不识别**：如遇长期停牌，最近一根 K 线可能很旧

## 七、与 czsc 的关系

| 引擎 | 关注 | 时间尺度 | 输出 |
|-----|-----|---------|-----|
| **DK 波段（v6.4.7）** | 短期波段择时 | 日级 | D/K 信号 + 持续天数 |
| **czsc 缠论（v6.4-v6.4.5）** | 趋势级别 + 中枢位置 | 日级 + 周级 | 笔/中枢/三买卖/共振 |

**建议组合**：
- **波段择时**：DK 信号触发日 = 进出场时机
- **位置确认**：czsc 周中枢位置 = 是否值得进场
- **双引擎共振**：DK D 信号 + czsc 共振强多 = 高胜率买点
- **双引擎背离**：DK D 信号 但 czsc 当前价 ≫ 周中枢上沿 = 假买点（参考东材案例）
