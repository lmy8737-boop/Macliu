# 反偷懒审计协议 (Anti-Laziness Audit Protocol) v1.0

## 适用范围
仅用于 `FULL_7_AGENT` 中 5 号监工对本轮**实际参与角色**产出的深度质量审核；`LIGHT_COMMITTEE` 不加载本协议，也不得据此声称独立审计。本协议是在现有幻觉审计、评分卡、风控红线之上的**第四道审核层**。下文按角色列出的检查项只在该角色实际参与且任务触发对应职责时适用，不为凑流程增加角色或交易输出。

审计基于 3 号按变量维护的共用证据表：角色只需贡献职责内的增量判断，不重复采集同一事实。减少重复搜证不得削弱 A 级变量一手核验、时效、口径、复算、来源登记或最强反方；确需独立第二意见时，必须保留独立取证路径。

---

## 一、浅析检测 (Shallow Analysis Detection)

### 1.1 模糊废话词库 (Buzzword Blacklist) — 命中 ≥3 处 → 自动 REJECT

以下词汇/句式在无具体数据或事件支撑时视为"废话填充"：

| 类别 | 模糊表达（禁止） | 合规替代（必须） |
|------|----------------|----------------|
| 情绪类 | "市场情绪改善/恶化" | "北向资金单日净流入83亿+融资余额5日上升→情绪回暖" |
| 趋势类 | "有望受益于" | "公司Q1订单同比+47%，直接受益于XX政策第3条" |
| 政策类 | "政策利好/政策支持" | "国务院5月20日发布《XX意见》第7条明确补贴标准" |
| 估值类 | "估值合理/估值不贵" | "当前PE 23x vs 行业中位数31x，PEG 0.8" |
| 方向类 | "存在上行空间" | "中性情景目标价¥45（+18%），触发条件：Q2营收>12亿" |
| 对冲类 | "注意风险" | "核心风险：客户A占营收38%，若丢失→EPS下降42%" |
| 时间类 | "近期/短期" | "未来2-4周"/"6月15日前" |
| 因果类 | "受多重因素影响" | 列出≥2个具体因素+各自权重 |

### 1.2 深度指标硬门槛（不达标 → REJECT）

| 角色 | 检查项 | 硬门槛 | 判定方式 |
|------|--------|--------|---------|
| 1号 | 配置建议引用的数据点数量 | ≥ 5 个独立数据源（附日期） | 计数：有日期的数据引用 |
| 1号 | 周期定位置信度解释 | 必须列出 ≥2 个支撑信号 + ≥1 个矛盾信号 | 只有正面论据=浅析 |
| 2号 | 每只深度标的独立催化剂 | 必须有 ≥1 个非行业共性的个股催化剂 | "行业β"不算深度 |
| 2号 | 竞争对手对比 | 深度卡片必须提及 ≥1 个同业对标 | 孤立分析=不完整 |
| 3号 | 数据时效标注 | 每个数据点必须有采集时间戳 | 无时间戳=不可验证 |
| 4号 | 信号独立推导过程 | 必须展示从 structures.json 到信号的推导链 | 直接给结论=不可审计 |
| 4号 | 与上游矛盾时的处理 | 若方向与1号/2号矛盾，必须明确声明并说明原因 | 沉默矛盾=偷懒 |

### 1.3 "独立见解"检测

每个角色产出必须包含至少 **1 个逆向观点/风险提示**，即：
- 1号：当前周期定位的反面证据（为什么可能判断错误）
- 2号：推荐标的的最大下行风险（不是笼统的"市场风险"）
- 4号：当前信号的失效条件（具体价位或事件）

**缺少逆向观点 = 立即 REJECT，REASON: "缺少逆向思考，分析沦为推销"**

## 二、数据核实协议 (Data Verification Protocol)

本节的证据字段与状态统一引用 `../../research-data-verify/SKILL.md`（本包同级目录）的「Canonical Evidence Semantics」。工具名只表示获取通道；来源等级、主张类型、验证状态、获取状态和 `as_of` 必须分开记录。单份 P0 是 `original_checked`，只有独立信息链对同一口径数字差异≤2%才是 `independent_cross_checked`。

### 2.1 交叉验证规则

| 数据类型 | 验证方法 | 容差 | 失败处理 |
|---------|---------|------|---------|
| 股价/涨跌幅 | 对比 3号 scanner JSON 原始值 | ±1% | REJECT + 标记幻觉 |
| PE/PB/市值 | 对比原始结构化值并复算；工具名不作证据级 | ≤2% | 超过即标 `conflicted` + REJECT |
| 宏观指标(PMI/CPI) | 对比官方发布日期+数值 | 精确匹配 | REJECT |
| 行业增速 | 必须标注数据来源+发布日期 | N/A（来源检查） | 无来源=REJECT |
| 缠论结构引用 | 对比 structures.json 字段值 | 精确匹配 | REJECT + 严重幻觉 |

### 2.2 时效性检查

- **硬门槛**：按 T0/T1/T2 分别检查 `as_of` 与 freshness 要求；T0 必须当日，T1 核到最新季度，T2 标来源日期。
- **获取状态**：本次取数另记 `ok/partial/empty/stale/error`，不得用“接口成功”代替时效合格。
- **违反**：REJECT + REASON: "引用数据过期 [X天前/旧季度]，必须更新至最近可用数据"

### 2.3 "凭空数据"红旗

如果产出中出现以下情况，5号必须要求原角色提供数据来源：
- 精确到小数点后两位的增速数据（无来源标注）
- "据了解"/"据悉"/"市场传闻" 开头的信息
- 研报观点未标注发布机构和日期

**红旗 ≥2 处 → REJECT，即使其他内容正确**

## 三、返工质量验证 (Rework Quality Protocol)

### 3.1 语义差异检测（Semantic Diff）

当角色被 REJECT 后重新提交时，5号必须执行以下检查：

**Step 1：变更量化**
- 统计修改后版本相对原版的**实质性变更数量**（不计标点/格式/语序调整）
- **硬门槛**：实质性变更 ≥ 原版 REJECT 意见中提出的问题数量

**Step 2：逐条对照**
对5号原始 REJECT REASON 中的每一条意见：
```
| 原始意见 | 是否已修改 | 修改内容摘要 | 质量评估 |
|---------|-----------|------------|---------|
| "PE数据错误" | ✅ 已修改 | "44.78→47.2 已更正" | PASS |
| "缺少止损位" | ❌ 未修改 | N/A | FAIL |
```

**Step 3：判定规则**
- 所有意见均已实质性回应 → PASS
- 任何一条意见未修改或仅表面修改 → 再次 REJECT（相同 REASON + "返工敷衍" 标签）
- "表面修改"定义：
  - 仅增加/删除修饰词（"较为"→"非常"）
  - 仅调换段落顺序
  - 仅添加 disclaimer（"注意风险"）但未解决实质问题
  - 换了一个同样模糊的表达替代原表达

### 3.2 返工升级机制

| 返工次数 | 5号审核标准 | 附加要求 |
|---------|-----------|---------|
| 第1次返工 | 标准审核 + 逐条对照 | 必须输出 semantic_diff 表格 |
| 第2次返工 | 严格模式（任何残留问题=REJECT） | 系统自动标记 [累犯] |
| 第2次仍REJECT | 熔断 FORCED_PASS | 标记 [高风险未决+返工敷衍] |

### 3.3 反"最小改动"策略

5号在审核返工稿时，禁止因为"比上次好了一点"就放行。标准是：
> **"如果这是第一次提交，以当前质量能否 PASS？"**

如果答案是"不能"，则继续 REJECT。不因为是返工稿就降低标准。

## 四、职责增量与独立取证验证

### 4.1 共用证据表与变量分工

5号检查每个实际参与角色是否围绕分派变量提供职责增量：

| 检查项 | 合格标准 | 违规判定 |
|------|---------|---------|
| 变量归属 | 每个关键变量有取证责任和最相关的解释角色 | 无责任人或多人重复抓取同一事实却口径不一致 |
| 角色增量 | 给出本职责下的解释、假设、反方或证伪条件 | 只复述共用证据表或其他角色结论 |
| 证据复用 | 引用共用证据表的行号/变量名，不伪装成独立取证 | 把共享底稿改写后称为独立验证 |
| 交易边界 | 4 号只在明确交易意图下参与 | 比较、排名或非交易研究自动生成仓位/动作 |

角色结论相同不等于缺乏独立判断；判断标准是是否有职责内增量和可核验证据，而不是强迫角色故意唱反调、另找标的或凑出分歧。

### 4.2 自动 REJECT 触发条件

1. 角色只有共享事实的改写，没有职责内增量判断、反方或证伪条件。
2. 把共用证据表或上游角色结论称作“独立审计/独立验证”。
3. 任务没有交易意图，却加载 4 号或输出仓位、止损、买卖动作。
4. 为省 token 省略 A 级变量的一手核验、口径、时间戳、复算或来源缺口。

### 4.3 何时保留独立第二意见

出现以下任一情形，可指定第二角色独立取证：未决 A 级变量会显著改变论点/估值/动作；两个独立信息链互相冲突；R 级决策需要额外确认。第二角色应从原始来源或独立信息链重新检索，记录 `source_level`、`verification_status`、`retrieval_status` 与 `as_of`，再与共用证据表对照。只阅读主分析后表示赞同，不算独立第二意见。

## 五、5号自身反偷懒约束

为防止5号本身偷懒（给个 PASS 了事），增加以下自检：

### 5.1 最低审核密度

- 审核报告总字数 ≥ 800 字（不含模板框架）
- 每个实际参与且需要审核的角色评语 ≥ 100 字
- 必须引用至少 3 个具体数据点进行交叉验证

### 5.2 禁止空洞 PASS

PASS 报告必须包含：
- 每个角色的 1 个具体优点（引用原文）
- 每个角色的 1 个改进建议（下期改进，不影响本次 PASS）
- 如果本次产出质量明显低于上期但仍 PASS，必须说明理由

### 5.3 REJECT 必须可执行

REJECT REASON 必须满足：
- 指出具体位置（"第X段/第X行/标的XXX"）
- 给出明确修改方向（不是"请改进"而是"请补充XXX数据"）
- 可量化的完成标准（"添加≥2个数据源"而非"增加数据支撑"）

## 七、与 review_router.py 联动

### 新增状态码扩展

```
STATUS: REJECT
REJECT_TYPE: SHALLOW|UNVERIFIED|PERFUNCTORY_REWORK|COPYING
REASON: <具体意见>
```

- `SHALLOW`：浅析/模糊
- `UNVERIFIED`：数据未核实
- `PERFUNCTORY_REWORK`：返工敷衍
- `COPYING`：互相抄袭

### 路由行为差异

| REJECT_TYPE | 路由行为 |
|-------------|---------|
| SHALLOW | 回炉对应角色 + 额外要求："必须补充具体数据支撑" |
| UNVERIFIED | 回炉3号（数据源头）+ 对应角色 |
| PERFUNCTORY_REWORK | 回炉 + 降低剩余重试次数 |
| COPYING | 回炉下游角色 + 强制要求："必须展示独立分析过程" |

## 八、熔断保护

即使是反偷懒审计，也不能无限循环：
- 反偷懒导致的 REJECT 计入同一个 MAX_RETRIES=2 计数器
- 但 FORCED_PASS 时会额外标注具体偷懒类型，供月度考核扣分
- 月度累计 FORCED_PASS(偷懒类) ≥ 3 次 → 触发该角色 Prompt 重写
